## 上线：发布为公网链接

- 用户诉求：不想每次在电脑起项目，手机输链接就能用；项目无后端，可静态托管。
- **线上地址：https://my-os-workspace.app.workbuddy.host/**（appName「My OS 个人工作台」，domainPrefix `my-os-workspace`，deployedAs http-service）。管理入口：设置—数据管理—应用。
- **关键坑：部署必须监听平台注入的 `PORT`**。首次部署失败（`service did not become reachable on port 3000`），原因是 vite.config.ts 写死 `server.port: 5173`，而沙箱注入 PORT=3000、detect 出的启动命令是 `vite --host 0.0.0.0`。
- 修复：`vite.config.ts` 顶部 `const port = Number(process.env.PORT) || 5173`，`server` 与 `preview` 都用该 port，并都加 `host: '0.0.0.0'` + `allowedHosts: true`（Vite 6.4.4 支持）。为此新增 devDependency `@types/node`（配置里要用 `process.env`）。
- 路由是 createWebHistory（history 模式），靠 vite dev 自带的 SPA 回退让 /agent 等深链接与刷新可用；实测 /、/agent、/health、/notes 均 200。**不要改用 dist + static 托管**：python http.server 无 SPA 回退会让深链接 404，且换目录会被平台当成另一个 app。
- 本地验证 PORT 生效：`PORT=4321 ./node_modules/.bin/vite` → 绑 4321 返回 200。

## 承载与状态模型（用户提问确认）

- 线上链接承载：DNS `my-os-workspace.app.workbuddy.host` → CNAME `*.clb.bj-tencentclb.cloud`（腾讯云负载均衡，北京），IP 49.233.240.214；响应头 `Server: CloudStudio Gateway` + `Eo-Cache-Status/Eo-Log-Uuid`（腾讯云 EdgeOne）。即整套在腾讯云，WorkBuddy 内置托管服务提供域名与沙箱，用户无需自购服务器。
- **状态是「每设备 + 每域名」一份**：localStorage key `myos.state.v1`，存 theme / checks（周任务勾选）/ weekStatus / videoStatus / sidebarOpen。md 里的 status 只是初值，浏览器覆盖优先。**同一台电脑上 localhost:5173 与线上域名也是两份独立状态**（origin 不同）。清缓存/无痕模式会清零。
- 结论：手机与电脑不同步是设计使然；要同步需引入后端（WorkBuddy 云服务 + 登录）或 Git 回写 md，属可选后续。
