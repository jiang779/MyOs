## 〇、先搞清楚一件事：项目里有「两套地图」

|    | 通用组件引擎 `TdtMap`          | 大屏海图 `AMapSeaMap` |

> "我在项目里做了两套基于天地图的地图。一套是通用组件引擎，把选点、画区域、态势图这些场景封装成可复用的组件，；一套是海防大屏，独立实现，因为它的海量点位、实时数据、工具交互这些需求跟通用组件的设计前提不一样。"

# 第一部分：通用组件引擎 TdtMap（面试主菜）

## 一、这个引擎到底是干嘛的（30 秒讲清楚）

**用大白话说：** 天地图官方只给了很底层的 JS 接口（画个点、画条线、画个圈），直接用很麻烦、还有一堆坑。项目里很多地方要用地图——表单选点、画作业区域、详情弹窗态势图……每个场景都重写一遍又乱又容易出错。

**所以我做了一套统一的地图组件**，把这些场景抽象成几个"模式"（选点、多点、轨迹、画圈、作业区块、态势图），业务方传 `mode="single"` + 绑定数据就能用。等于把"难用的底层"包装成"好用的组件"。

### 代码实现思路（一条完整链路，面试按这个顺序讲）

整套引擎分两大阶段：**先"把地图准备起来"（加载 SDK + 建图），再"地图上干活"（点击选点、画线画圈）。**

#### 第一阶段：把地图准备起来（前期加载）

```
① 业务页面（最外层）
   <tdt-map mode="single" v-model="point" />
   只传「模式 + 数据」，不碰任何地图细节

② 入口组件（index.vue）
   按 mode 分发：single → TdtMapSingle、multi → TdtMapMulti……
   用 Vue 动态组件 <component :is="..."> 切换

③ 公共 mixin（tdt_map_mixin.js，核心）
   所有子组件 extends 它，共享同一份「加载 + 建图」逻辑：
     loadScript(key)  加载天地图 SDK
       ├─ window.__tiandituLoading 标记防重复（只下载一次）
       ├─ document.createElement('script') + src 拼 key  动态加载
       └─ script.onload 下载完成 + 轮询检查子 API 是否就绪 → resolve(window.T)
     拿到 T 对象后 → new T.Map(...) 建地图
```

**两个容易卡壳的点，提前想清楚**：

1. **`resolve(window.T)` 返回了什么？** 不只是"通知完成"，而是把天地图的 `T` 对象（含 Map / Marker / Circle 等全部功能）作为结果传出去。调用方靠这个 `T` 才能 `new T.Map()`。类比：`loadScript` 是"去仓库领工具箱"，`resolve(工具箱)` 是"真的把工具箱递到你手里"。
2. **`window.__tiandituLoading` 在哪定义？** 没有专门声明，第一次调用时直接 `window.__tiandituLoading = true` 现挂上去。`window` 是浏览器自带全局对象，往它身上赋值就是"全局放一个变量"，全页面共享，所以能防重复加载。

#### 第二阶段：地图上干活（真正业务交互）

地图建好后，六个子组件的差异体现在"用户点一下地图时怎么处理、画成什么"。核心三个问题：

**① 点一下是「覆盖」还是「追加」？**

- 覆盖（单点）：新的来、旧的没。业务上"选一个定位点"，一个就够。类比钉图钉——墙上永远只有一个。
- 追加（多点/轨迹/边界/区块）：新的排到旧的后面。业务上要"收集多个点"。类比串珠子——越串越多。

**② 画成「点 / 线 / 面」？**

- 多点：散点不连线（一堆图钉）。
- 轨迹：按顺序连成折线。
- 边界/作业区块：连成闭合多边形（围出区域）。

**③ 数据是「对象 / 数组 / 分组区块」？**

- 单点：`{ lng, lat }` 对象。
- 多点/轨迹/边界：`[{ lng, lat }, ...]` 数组。
- 作业区块：`[{ name, points: [...] }]` 分组。
- 态势图：无 v-model，数据从 props 传入，只展示。

**六种模式对照表（重点背）**：

| mode      | 业务场景     | 覆盖/追加  | 画成什么    | 数据形状     |
| --------- | -------- | ------ | ------- | -------- |
| single    | 选一个定位点   | 覆盖     | 点       | 对象       |
| multi     | 标记多个点    | 追加     | 散点      | 数组       |
| track     | 画一条轨迹    | 追加     | 折线      | 数组       |
| boundary  | 圈一块边界    | 追加     | 闭合多边形   | 数组       |
| areas     | 画多块作业区   | 追加（分组） | 多个闭合多边形 | 分组数组     |
| situation | 详情弹窗只读展示 | 不可点    | 线+面+标注  | props 传入 |

**一句话串全流程（背下来）**：

> "业务页面传 `mode` + `v-model`；入口组件按 mode 分发；子组件继承公共 mixin，先 `loadScript` 加载 SDK、`new T.Map` 建地图；之后单点模式点击是'覆盖'，多点/轨迹/边界是'追加'，最后按模式画成散点、折线或闭合多边形，数据通过 `v-model` 同步回业务层。"

## 二、六大模块 · 大白话话术卡（核心，重点背）

每一块记住三句话：**它干嘛 → 怎么做的 → 解决了什么**。

### 模块 1：脚本加载管理

- **干嘛**：天地图要加载一个外部 JS（SDK），是异步的，且 SDK 内部多类功能不是同时就绪。
- **怎么做的**：写加载器，用全局标记保证"SDK 只加载一次"；加载完轮询检查"地图、标记、圆圈等功能类是否真的准备好了"，好了才放行，超时报错兜底。
- **一句话**："我做了幂等的 SDK 加载器，保证 SDK 只加载一次、且等它真正就绪才初始化，避免并发重复加载和半就绪状态。"

### 模块 2：多模式统一封装

- **干嘛**：一个入口组件，按"模式"分发到不同子实现。
- **怎么做的**：用 `mode` 区分六种场景，用 Vue 动态组件 `<component :is>` 切换；对外统一 `v-model`，内部数据归一化。
- **一句话**："一个入口 + 模式分发，六种地图交互统一成一套组件，对外接口一致，内部各自实现。加新模式只需加一个子组件 + 一行分发判断。"

### 模块 3：踩坑修复（★★★ 前端岗最容易追问、最加分）

**坑 A：切换底图后拖不动了**

- 天地图的 `setMapType` 会重置拖拽 handler，切完底图地图就拖不动。
- 解决：切完底图强制重新调 `enableDrag` / `enableScrollWheelZoom` / `enableDoubleClickZoom` 三个方法。
- 一句话："天地图 setMapType 会重置拖拽 handler，我切完底图后强制重新 enableDrag 等交互。"

**坑 B：拖动标记时，地图误以为你"点了一下"**

- 天地图把"标记上的按下/拖动"透传成"地图点击"，导致拖一下就多打一个点。
- 解决：用时间戳判断——距按下时间太近的"点击"当成拖动副作用忽略；拖动结束时也记时间戳，区分"拖完的点击"和"真正想删除的点击"。
- 一句话："用时间戳抑制了天地图把顶点拖动透传成地图点击的问题。"

**坑 C：标记拖动不依赖天地图自带 API**

- 天地图标记拖拽接口各版本行为不一致。
- 解决：自己监听 mousemove/mouseup 实现"跟手移动 + 松手落定"；拖动中只移动图形做预览，松手才写回数据；把 mouseup 挂到 document，鼠标移出画布也能结束拖动。
- 一句话："顶点拖动手动实现跟手移动 + 松手落定，不依赖天地图自带拖拽，还做了移出画布能结束拖动的兜底。"

**坑 D：弹窗里地图初始化时尺寸是 0**

- 弹窗打开有动画，动画期间容器宽高为 0，直接初始化会失败。
- 解决：轮询等容器尺寸可用，超过次数报错提示，不死等。
- 一句话："处理了 el-dialog 动画期间容器尺寸为 0 导致的初始化失败，轮询 + 重试上限兜底。"

### 模块 4：坐标系转换

- **干嘛**：国内地图坐标（火星坐标 GCJ-02）和 GPS 真实坐标（WGS84）有偏差。
- **怎么做的**：实现标准纠偏算法，把高德/腾讯那种加密坐标转回天地图能正确显示的坐标；只对国内纠偏，国外原样返回。
- **一句话**："实现 GCJ-02 到 WGS84/CGCS2000 的坐标纠偏，解决国内地图坐标和真实 GPS 坐标对不上的问题。"

### 模块 5：视野自适应

- **干嘛**：多个点时，自动缩放到"所有点刚好都显示"。
- **怎么做的**：用墨卡托投影公式，根据点位范围 + 容器尺寸反算最合适的 zoom，再定位中心。
- **一句话**："根据点位范围用墨卡托投影反算 zoom，让所有点自适应入镜，而不是简单 getBounds。"

### 模块 6：性能优化

- **怎么做的**：① 网格线"画多了记下来"，平移时视野还在已画范围内就跳过重绘；② 按 zoom 动态调网格密度 + 数量上限；③ 覆盖物统一登记管理，销毁时一次性清干净；④ 搜索输入防抖（600ms）。
- **一句话**："网格线用覆盖区缓存避免重复绘制，按 zoom 调密度并做数量保护，覆盖物统一管理销毁时无残留。"

## 三、追问清单 + 标准答案（重点背"为什么"）

### 追问 1："为什么不直接用现成的 Vue 地图组件库？"

> 三个原因。一是我们用的是天地图（国家官方平台），市面上组件库大多基于高德或百度，天地图封装很少。二是交互场景特殊——选点、画作业区、手动输坐标、态势图，通用库满足不了。三是天地图有一堆 API 的坑，与其到处打补丁，不如集中封装一次，后面都受益。

### 追问 2："坐标纠偏的原理？"

> 国内地图服务商不能直接用真实 GPS 坐标，会用公开算法做偏移得到"火星坐标"。这个偏移有规律、可逆。我实现这个公开算法的逆运算，把火星坐标还原成天地图能对齐的真实坐标。核心是"加密往一个方向偏，我反向减掉偏移量"。只对国内坐标做，因为加密只在国内生效。

### 追问 3："地图卡顿怎么优化？"

> 三招。一是减少不必要重绘——网格线画时往外多画一圈，平移时视野还在范围内就整次跳过。二是控制数量——网格密度跟 zoom 走，设上限防画几千条线。三是规范生命周期——所有图形统一管理，切换数据或销毁时一次性清理，防止内存越积越多。

### 追问 4："拖动标记为什么自己实现，不用天地图自带的？"

> 两个考虑。一是兼容性——天地图拖拽接口各版本行为不一致。二是控制粒度——自己实现能"拖动时只移动图形做预览、松手才写回数据"，不高频触发更新，也方便处理"鼠标移出地图再松手"。

### 追问 5："怎么保证代码质量和可维护？"

> 分层。工具函数（坐标转换、脚本加载、搜索）是纯函数独立成文件；公共逻辑（初始化、渲染、视野）抽成 mixin 六模式复用；各模式差异独立成子组件；对外只暴露一个入口，有清晰 props/事件协议。加新模式、改某模式都不影响其他场景。

### 追问 6："v-model 怎么同时支持对象和数组？"

> 用 mode 区分。单点数据是 `{lng,lat}` 对象，多点/轨迹/边界是数组。内部统一归一化成数组处理，只在"往外输出"这一步按模式决定输出对象还是数组。对外自然，内部统一。

### 追问 7："大屏为什么不用你封装的那套组件？"（★★★ 一定会问，重点准备）

> 不是偷懒，是两套东西的设计前提不一样。`TdtMap` 是面向"表单选点、画区域"的编辑型组件，它假设数据是用户自己点出来的、数量很少（个位数到几十个）。而大屏是"实时态势展示"——成百上千个点位、要聚合、要视口剔除、数据是接口实时推的、还要做测距测面等工具交互。这些能力 `TdtMap` 里一个都没有，硬套等于重写。所以大屏独立实现，两者只是共用同一个天地图 SDK。这也让我很清楚组件化的边界——它适合"可复用、数据量小、交互标准"的场景，不适合"高度定制、海量数据、实时刷新"的场景。

# 第二部分：海防大屏 AMapSeaMap（独特技术）

> 大屏虽然没封装成组件，但**技术含量很高、甚至比通用组件更难**。它解决的是"海量点位 + 实时数据 + 复杂工具"下的渲染和交互问题。下面这些点，是你在大屏这块能拿得出手的硬货。

## 大屏的核心难点（一句话）

> 通用组件处理的是"几十个点"，大屏处理的是"上百移动的点 + 实时刷新 + 测距测面等工具"，核心挑战是**性能**和**复杂交互**。

## 大屏的独特技术（按重要度排）

### 1. 海量点位渲染优化（★★★ 最核心）

- **视口剔除**：只渲染当前屏幕看得见的渔船，屏幕外的不画，减少标记数量。
- **渔船聚合**：重叠的渔船自动圈成（也有画圈、画方形、多点连区域形成）一个"聚合点"，点圈弹出列表选择（用 supercluster 算法）。默认关闭时走"螺旋错位 + 视口剔除"。
- **螺旋错位**：坐标完全重叠的船，自动错开排布，避免叠成一坨。
- **低 zoom 降级**：缩放级别低（全景视角）时只显示简化图标，不显示船名和脉冲圈，放大后恢复。
- **一句话**："大屏有几百上千个移动点位，我做了视口剔除、渔船聚合、螺旋错位、低 zoom 降级这一整套渲染策略，保证海量点位下地图不卡。"

### 2. 空间几何算法

- **Haversine 距离**：算两个经纬度点的球面距离（测距、圈搜用）。
- **点在多边形内判断**：射线法，多边形搜用。
- **球面多边形面积**：测面积用（不是简单平面面积，是球面上的面积）。
- **一句话**："实现了 Haversine 距离、射线法判点在多边形内、球面多边形面积等空间算法，支撑测距测面圆搜矩形搜。"

### 3. 工具绘制（测距/测面/矩形搜/多边形搜/圆搜）

- 手动实现整套绘制交互：橡皮筋线、顶点标注、右键/双击/回车结束、撤销、取消。
- 绘制期间**禁用点位点击**、**暂停双击缩放**（避免"双击结束绘制"顺带把地图放大一级）。
- 判断"鼠标是否悬停在 UI 上"，避免点到按钮时误触绘制。
- **一句话**："工具绘制是我手动实现的完整交互，包括橡皮筋、顶点标注、多种结束方式，还处理了绘制期间禁用点位点击、暂停双击缩放这些冲突。"

### 4. 视野与飞行

- **所有港口 zoom 反算**：首屏根据"所有港口范围"反算一个能装下全部港口的 zoom。
- **只平移不改 zoom**：聚焦渔船/告警时只 panTo 不改 zoom，避免"先拉远再拉近"的缩放动画，也避免港口参照被缩小。
- **港口飞行**：点击港口平滑飞到该港口。
- **一句话**："首屏按全部港口反算最佳 zoom，聚焦时只平移不改 zoom，避免缩放动画和瓦片重拉导致的卡顿。"

### 5. 轨迹与聚焦渲染

- **渐变轨迹**：透明度从最旧点渐变到最新点，带方向箭头、起止端点、动/静线宽。
- **轨迹点 hover**：鼠标悬停轨迹某点显示该点的时间、方向、坐标详情。
- **一句话**："轨迹用渐变透明度区分新旧、带方向箭头和起止点，还做了轨迹点 hover 显示详情。"

### 6. 脉冲/闪烁动画

- 告警点脉冲圈、聚焦船呼吸放大、区域闪烁定位等，全部用定时器 + 手动改覆盖物半径/透明度实现。
- **一句话**："告警脉冲、船呼吸、区域闪烁这些动画，是手动用定时器改覆盖物属性实现的，不依赖第三方动画库。"

### 7. 网格线性能（比通用组件更重）

- 覆盖区缓存：平移时视野还在已画范围内就跳过重绘。
- 按 zoom 动态调密度 + 数量保护（单方向超 48 条自动放大间距）。
- 矢量图黑线、影像图白线自动换色。
- **一句话**："网格线做了覆盖区缓存和数量保护，避免海图场景下平移缩放反复重绘几千条线导致卡顿。"

## 大屏 + 通用组件的"对比"是你的加分项

面试时可以主动讲这个对比，体现你有反思：

> "项目里是两套地图。通用组件走组件化、数据驱动，20 多个场景复用；大屏因为海量点位、实时数据、工具交互这些特殊需求独立实现，虽然没抽成组件，但它的渲染优化（视口剔除、聚合、螺旋错位）和工具绘制其实比通用组件更难。这两套的对比让我很清楚组件化的边界在哪。"

## 四、面试技巧：主动引导，扬长避短

**主动往"踩坑"和"设计思路"上引导，别被动等对方问代码细节。**

- 问"你做了什么"→ 讲模块 + 讲踩坑（坑 A/B/C/D 是王牌）。
- 问"为什么这么写"→ 讲"当时遇到什么问题，所以这么设计"。
- 问到大屏 → 讲"两套地图的区别 + 大屏的渲染优化"。
- 被问到看不懂的 API → 坦诚"这块是 AI 辅助生成，我主要负责架构设计和问题定位"，然后拉回你熟悉的部分。

> ⚠️ 诚实提醒：不要假装精通每个 API。一问 `enableDrag` 源码、`supercluster` 内部机制，硬编会露馅。**承认"AI 辅助 + 我负责设计和验证"是现在业界能接受的真实协作方式**，关键是讲清楚"为什么这么设计、解决了什么问题"。

## 五、考前 30 分钟速记版

**通用组件（TdtMap）**：

1. 一句话：把天地图难用的底层封装成好用的 Vue 组件，20+ 场景复用。
2. 六模式：选点/多点/轨迹/画圈/作业区块/态势图。
3. 四坑：切底图拖不动、拖动误判点击、拖动自己实现、弹窗尺寸 0。
4. 两算法：坐标纠偏、视野自适应反算 zoom。
5. 三优化：网格覆盖区缓存、按 zoom 调密度+上限、覆盖物统一清理。

**大屏（AMapSeaMap）**：  
6\. 渲染优化：视口剔除、渔船聚合、螺旋错位、低 zoom 降级。  
7\. 空间算法：Haversine 距离、射线法判多边形、球面面积。  
8\. 工具绘制：测距/测面/圆搜/矩形搜/多边形搜，手动实现全套交互。  
9\. 视野：全港口反算 zoom、只平移不改 zoom。  
10\. 对比话术：组件化 vs 大屏独立实现，说清组件化的边界。
