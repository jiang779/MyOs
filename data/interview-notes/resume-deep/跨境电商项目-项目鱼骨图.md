# 项目鱼骨图 · 葫芦岛市跨境电商综合服务平台

## 一、一句话

让企业能合规地把货报出去 + 让服务商能接到活 + 让平台能管住这两件事。

> 1、这句话在说什么
这句话把平台拆成了三个角色和一条数据链。企业是需求方，它要把货卖到境外，前提是合法出境并且单据齐全；服务商是供给方，它靠替企业干那些企业自己干不了的活赚钱；平台既不做货也不干活，它的价值在于把前两者撮合起来，同时对整个过程负责——谁能进来、能不能上架、单据对不对、钱怎么结、服务好不好，都得管。

所以“让企业能合规地把货报出去”是业务的起点，“让服务商能接到活”是供给侧的运转方式，“让平台能管住这两件事”是平台存在的理由。三者扣在一起，才是一个完整的商业闭环。

> 2、“报出去”是整件事的起点
出口货物依法必须向海关申报。跨境电商不能简单当作国际快递寄走，海关为它单独设了监管方式代码：9610 是零售出口，面向个人消费者，用清单申报；9710 是企业对企业直接出口，用报关单；9810 是先出口到海外仓再零售，同样用报关单。这三类在系统里各有一套页面，字段不同但结构同构。

申报的本质是向海关证明三件事：谁在卖、卖的什么、怎么卖的。对应的就是主体信息（企业的海关备案编码等）、货物要素（商品编码、品名、数量、单价、原产国、目的国）、以及单据数据。单据里最核心的是“三单”——订单、支付单、物流单。海关会把这三份数据比对，金额、主体、商品必须一致才放行，这就是“三单对碰”。它的作用是防伪报价格、防洗钱、防假订单真走私。

申报之后并不是“提交成功”就结束了，必须拿到海关回执。回执带有状态码，代表受理、审核、放行或退单等不同结果。只有拿到回执，这票货才算真正报出去，才能放行、装运、结汇、退税。也正因为海关那边已经有了数据，系统里申报后的单据会被锁定，不允许再改——改本地数据只会造成两边不一致。

> 3、报完之后的两件事：结汇与退税
这两件事都直接关系到钱，也是企业为什么必须合规申报的根本原因。

结汇是把境外收到的人民币以外的货币换成人民币回到国内账户。银行不能随便给你换，它要核实这笔外汇是真实贸易所得，凭证就是报关单或清单，加上合同、发票和物流单据。没有申报就没有报关单，银行不会给你结汇，钱就回不来。

退税是出口货物适用增值税零税率，企业把国内采购时已经付掉的进项增值税退回来。办理退税需要一条凭证链：出口退税专用的报关单、增值税专用发票、收汇凭证，三者要能对上。没有报关单，这条链断在第一步，税退不回来，利润直接少一块。

所以“报关单是贸易真实性的唯一凭证”——银行靠它结汇，税务靠它退税。这句话是整个跨境电商业务的地基。

> 4、谁来报
法律上的申报主体是卖货的企业，报关单上“境内收发货人”写的是它。但操作上有三条路。

第一条是企业自己报，前提是做过报关单位备案，有电子口岸的数字证书，有人会填。系统门户里那几个自助申报页面就是给这条路用的。

第二条是平台代报。管理端那六个申报页面，本质是平台帮没有报关能力的企业把单据录进去、把报文发出去。平台在这里是服务方，不是法定申报人。

第三条是委托报关行代报，也就是把这件事包给服务商。委托要走电子委托，报关单上会出现双抬头：经营单位是企业，申报单位是报关行。这也是判断一票货到底谁在操作的关键。

三条路用的是同一套单据，区别只在谁来做判断、谁来承担报错的后果。

> 5、既然点几下就能报，为什么还花钱找人
因为报关单的最后一步是点按钮，前面九成的工作是判断，而这些判断直接决定钱和责任。

商品归类是第一个门槛。同一个东西归到不同编码，税率、监管条件、能不能退税全都不一样，归错了轻则查验，重则补税罚款、退税失败。申报要素是第二个门槛，海关对每个编码都规定了必须填哪些项，材质、用途、规格、品牌，漏一项就退单。再往后是监管条件，有些商品要认证、要许可证、要检验检疫，不符合条件根本报不了。然后是价格申报，报得离谱会触发海关估价。最后是异常处理，查验、改单、删单重报、滞港，这些都需要有人在现场或系统里盯着。

还有一层是资质与责任。自主报关要备案，代理报关要有报关企业资质。报错了，责任在申报主体；企业把活外包出去，买的就是“专业判断 + 风险承担”。

所以现状很清楚：大企业养自己的关务团队，中小卖家按票外包给报关行。系统解决的是“怎么填”，服务商解决的是“填什么、填错谁负责”。而且平台代报通常也不是免费的，多半按票收费或打包在服务套餐里——所以这两者的差别从来不是钱多钱少，而是谁做判断、谁担责任。

> 6、服务商在接什么活
服务商接的是企业的活，企业有三个自己补不上的缺口。

能力缺口：不会报关、不懂归类，所以需要报关行和关务代理。资源缺口：没有国际干线、没有目的国清关资质、没有当地派送网络，所以需要货代、物流和仓储。资质与资金缺口：没有支付牌照、不会处理外汇和退税，所以需要支付机构和财税服务。再往外还有合规咨询（认证、标签、目的国法规）和技术服务（ERP、独立站、小程序）。

平台自己不干这些活，它做四件事：准入，服务商要经过两级审核才能进来，一级审资质完整性，二级审合规风控；上架，服务要审核过才能挂到市场；撮合，企业发需求、平台审核后推荐匹配的服务商；结算与治理，订单、账单、结算抽成，加上工单和评价审核。

这就是“让服务商能接到活”的完整含义：不是平台给活，是平台把企业的活变得可发现、可交易、可追责。

> 7、物流与海外仓为什么是刚需
企业有产品，不等于能把货送到买家手上。跨境物流是三段：头程从国内工厂或仓库到口岸再出境，清关在目的国过海关，尾程从目的国仓库派送到买家。企业通常只有第一段的能力——国内有仓、有快递，后两段完全空白。所以“物流需求”买的其实是这三段。

海外仓不是被迫，是模式选择。直邮是每单从国内发国际小包，时效七到二十天，单件运费高，退货几乎不可能；海外仓是整批运到目的国仓库备货，下单后当地发货，两到五天到货，运费摊薄，退换货能就地处理，代价是先压一批货、付仓储费、还要预测销量。所以销量稳定的爆款走海外仓，长尾和新品走直邮。

为什么不自己建海外仓：要当地注册公司、租仓、雇人、过消防和税务合规、上仓储系统。中小卖家一年发不了几个柜，自建纯亏，所以买第三方海外仓的仓配服务。系统里 9810 那个“订仓单”页面就是干这个的——先向海外仓订仓位和入库计划，再出报关单，然后整批发出去。

> 8、平台靠什么“管住”
管住这两件事，落在四个动作上。

第一是管准入：服务商两级审核，企业备案审核，需求审核，挂售审核。第二是管单据：申报页面、回执状态、二维码、模板导入，保证每一票货都有据可查。第三是管交易：订单、账单、结算、退款，把钱的路走通。第四是管服务过程：工单协同、派单规则、超时与评价，服务好不好有记录、有后果。

这四件事合起来，平台才不只是个信息展示网站，而是一个能把责任落实到具体主体和具体单据上的系统。

> 9、把链路连起来
一家企业进来，先备案，再发布需求；平台审核后推荐匹配的服务商；企业采购服务、下单、生成账单；货准备好后，无论自己报、平台代报还是报关行代报，最终都要落到同一套单据上——订单、清单或报关单、三单对碰、申报、回执；拿到回执，货出境，企业凭报关单去结汇和退税；过程中出问题就走工单，服务完成后评价，评价经平台审核进入服务商画像，影响它下一次能不能被推荐。

这条链路走通了，那句话就成立了：企业能合规地把货报出去，服务商能稳定地接到活，平台能管住准入、单据、交易和服务质量。

## 三、四条链路

| 链路 | 顺序 | 得到什么 |
|---|---|---|
| 企业上链 | 注册 → 备案 → 发需求 → 审核 → 推荐服务商 → 采购 → 订单 → 账单 → 工单 → 评价 → 评价审核 | 企业档案 + 需求池 → 才有撮合 → 才有交易流水 → 才有服务画像 → **匹配效率** |
| 一票货报出去 | 建订单 → 生成单据 → 申报 → 回执 → 状态锁定 | 有回执的申报单；**申报后不可编辑**（9610 走清单，9710/9810 走报关单） |
| 一票货的税算清 | 配税率（管理端）→ 门户填参数 → 完税价格 → 三税拆分 → 试算 → 导出 | 可报价、可留档的结果；价值是**报价有据可依** |
| 服务商变现 | 入驻两级审核 → 上架审核 → 被采购 → 接单 → 结算 → 评价 → 评级 | 可交易的服务 → 结算 → 平台抽成 → 曝光加权 |

## 五、三个结构事实

1. **9610 / 9710 / 9810 三套页面同构**（各 150 行上下），区别在监管方式、单据类型、字段。
2. **菜单全由后端下发**，每个模块旁的 `V*_menu_insert_*.sql` 是它的"户口"（菜单名 / 路由 / 组件路径 / 权限码）。一个页面 = 一个 `.vue` + 一条 `sys_permission`。
3. **同一件事常有两个入口**：门户自助 + 管理端代报/管理（申报、税费、备案都有）。
